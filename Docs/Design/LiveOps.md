## 1. 설계 원칙

1. **돌아오고 싶게, 압박 없이.** 순찰 보상·복귀 보상·이벤트는 "들어오면 좋은 것"이지 "안 들어오면 손해 보는 것"이 아니다.
2. **운영은 앱 업데이트 없이.** 공지, 이벤트, 상점 노출, 점검은 **원격 설정(Remote Config)**으로 바꾼다.
3. **혼자 운영할 수 있는 크기.** 고객 지원은 이메일 + FAQ로 시작한다. 사람 손이 많이 드는 기능(자유 채팅, 1:1 실시간 상담)은 뒤로 미룬다.
4. **법과 스토어 정책은 출시 조건이다.** 계정 삭제, 확률 공개, 개인정보 처리방침, 광고성 알림 동의는 없으면 출시할 수 없다.

## 3. 👤 계정과 로그인

### 3-1. 흐름
```
첫 실행 → 게스트로 바로 시작 (로그인 화면 없음)
   ↓ 1구간 보스 격파 후 (또는 첫 결제 직전)
"기기를 바꿔도 이어하려면 Google 계정을 연결하세요" [연결하기] [나중에]
   ↓ 연결
Google Play 게임즈 계정 연동 → 클라우드 저장 시작
```

| 항목 | 내용 |
|---|---|
| 게스트 | UGS Authentication **익명 로그인**. 바로 플레이 |
| 연동 | **Google Play 게임즈** (Android). iOS 출시 때 Apple 로그인 추가 |
| 연동 보상 | 💎 100 (계정당 1회) |
| 연동 권유 시점 | 1구간 보스 격파 직후, 첫 결제 직전, 설정 화면. **하루 1번 넘게 묻지 않는다** |
| 게스트 경고 | 게스트로 결제하려 하면 "기기를 잃으면 복구할 수 없어요" 안내 (결제는 막지 않음) |
| 닉네임 | 첫 보스 격파 후 정함. 2~10자, 금칙어 검사, 1회 무료 변경, 이후 💎 200 |

### 3-2. 클라우드 저장과 충돌
- 저장 시점: 판 종료, 기록 저장, 상점 구매 직후, 앱이 백그라운드로 갈 때
- **고르는 건 딱 한 번만:** **계정 연동 전(게스트)에 기기 저장과 서버 저장이 둘 다 있을 때만** 어느 쪽을 쓸지 고른다 (진행도가 높은 쪽에 "추천" 표시). **연동한 뒤에는 항상 서버 기준**([3-4](#3-4-다중-기기--오프라인--환불-회수))이고, 선택 화면은 다시 나오지 않는다.
- 그 한 번의 선택 화면은 **두 데이터의 요약을 보여주고 고르게** 한다.
  ```
  이 기기: 구간 3 · 칭기즈 칸 Lv14 · 💎 820 · 2026-11-02 21:10
  클라우드: 구간 4 · 칭기즈 칸 Lv17 · 💎 310 · 2026-11-03 08:22
  [이 기기 데이터 사용]  [클라우드 데이터 사용 (추천: 진행도가 높은 쪽)]
  ```
- **유료 보석·구매 기록은 서버가 기준**이라 어느 쪽을 골라도 줄지 않는다.

### 3-3. 계정 삭제 (Google Play 정책 필수)
- 계정을 만들 수 있는 앱은 **앱 안**과 **웹(게임 밖)** 두 곳에서 계정 삭제를 요청할 수 있어야 한다.
- 앱 안: 설정 → 계정 → **계정 삭제** → 남은 유료 보석이 사라진다는 안내 + 닉네임 다시 입력해서 확인
- 웹: GitHub Pages에 삭제 요청 안내 페이지 (사용자 ID + 연동 이메일로 요청). Play Console 데이터 보안 섹션에 이 URL 등록
- 처리: 요청 즉시 로그아웃 → **7일 유예** (그 사이 로그인하면 취소) → 완전 삭제
- 법령상 보관 의무가 있는 결제 기록은 분리 보관한다 (보관 기간은 출시 전 확인)

### 3-4. 다중 기기 · 오프라인 · 환불 회수

| 상황 | 규칙 |
|---|---|
| 기준 | **서버에 저장된 데이터가 기준**이다. 휴대폰 숫자는 표시용 |
| 같은 계정으로 동시 접속 | **나중에 접속한 기기가 이전 세션을 끝낸다.** 먼저 쓰던 기기에는 "다른 기기에서 접속해서 종료됐어요" 안내 후 로그인 화면으로 보낸다 |
| 오프라인에서 얻은 **무료 보상** (판 보상, 순찰 등) | 인터넷이 돌아오면 **서버가 검증한 뒤 반영**한다. 검증에 실패한 부분(시간 역행, 이상한 값)은 반영하지 않는다 |
| 오프라인에서 **무료 재화(골드 등) 소비** | 오프라인에서도 **쓸 수 있다.** 인터넷이 돌아오면 서버가 **거래 기록을 순서대로 다시 계산**하고, 다른 기기에서 이미 써서 불가능해진 거래는 **취소하고 재화를 돌려준다** |
| 오프라인에서 **유료 재화(보석) 소비** | **처음부터 온라인에서만 가능.** 오프라인이면 보석을 쓰는 버튼(상점, 뽑기, 닉네임 변경 등)이 잠기고 "인터넷에 연결해 주세요"가 뜬다 |
| 구글 결제 **환불**이 확인되면 | 그 구매로 지급한 보석을 **회수**한다. 이미 쓴 아이템(뽑은 장비, 올린 레벨 등)은 **회수하지 않는다** |
| 회수할 보석이 모자라면 | 잔액이 **음수**가 된다 (예: 💎 -300). **음수인 동안은 상점 구매를 막고**, 이후 얻는 보석으로 먼저 채운다. 게임 플레이는 그대로 할 수 있다 |
| 안내 | 환불로 회수·음수가 생기면 우편함과 상점 화면에 이유를 알려준다 |

- 위 내용은 **이용약관에 적는다** (19장). 환불 내역 확인은 구글 환불(취소된 구매) 내역 API로 한다 (14장).

## 4. 📬 우편함

| 항목 | 값 |
|---|---|
| 들어오는 것 | 랭킹 보상, 운영 보상(점검·사과), 쿠폰, 이벤트 보상, 친구 선물(넘친 것), 결제 누락 재지급 |
| 보관 기간 | 운영·랭킹 보상 **30일**, 친구 선물 **7일**. 남은 기간을 우편마다 표시 |
| 최대 | 100통 (넘치면 가장 오래된 **받은 우편**부터 정리, 안 받은 보상은 지우지 않음) |
| 버튼 | [모두 받기] |
| 표시 | 로비 위쪽 우편 아이콘 + 빨간 점 |

- 서버: Cloud Code `GetMail` `ClaimMail` + 플레이어별 우편 데이터. **받기는 서버에서 처리**(두 번 받기 방지)
- 오프라인에서는 우편함을 열 수 없다.

## 7. 📅 이벤트 운영 캘린더

### 7-1. 이벤트 종류

| 종류 | 주기 | 내용 | 보상 규모 (한 번에) |
|---|---|---|---|
| **영웅 기념 이벤트** | 영웅 기념일마다 | 해당 영웅으로 하는 미션, 한정 칭호·프레임 | 💎 200 + 🎫 1 + 칭호 |
| **계절 이벤트** | 분기 1회 | 할로윈(망각의 군단 유령 테마), 겨울, 설·추석 출석 | 💎 300~500 + 🎫 2~3 + 한정 프레임 |
| **주말 보너스** | 매주 토·일 | 던전 골드 ×1.5 | 🪙 |
| **서바이벌 변형 규칙** | 2주마다 | "적 속도 2배", "액티브만" 같은 특별 규칙 | 💎 50 + 칭호 |
| **신규 영웅 출시** | 업데이트 때 | 출시 기념 출석 7일 | 💎 300 + 영웅 조각 🧩 |

- **첫 이벤트는 출시 4주 차**에 연다. (이벤트 던전은 3구간 보스 격파 후 열리므로, 그 전까지는 이벤트 미션·출석 위주로 진행하고 이벤트 던전 입장 조건을 이벤트 안내에 표시한다.) 시즌 달력(출시일 다음 월요일 05:00 KST 시작, 28일 주기)은 [Missions 8장](Missions.md#8-시즌-패스-28일-6500)과 같다.
- 큰 이벤트는 **한 달에 1개**, 겹치지 않게. 이벤트 보상은 미션으로 주고, 따로 이벤트 재화를 만들지 않는다.
  - 이벤트 상점이 꼭 필요하면 **이벤트 토큰**을 쓰되, 이벤트가 끝나면 남은 토큰을 🪙로 자동 바꿔준다. (재화 종류가 늘지 않게)

## 8. 🛡️ 오프라인 보상 (순찰)

> **추천: 넣는다, 작게.** "들어오면 받을 게 쌓여 있다"는 하루 2~3번 접속할 이유가 된다. 대신 힘이 아니라 골드만 준다.

| 항목 | 값 (임시) |
|---|---|
| 쌓이는 것 | 🪙 **시간당 150** + 깬 구간 × 20 (5구간이면 시간당 250) |
| 최대 저장 | **12시간** (🪙 1,800 ~ 3,000) |
| 보석·🎫·장비 | 주지 않는다 |
| 빠른 순찰 | 광고 보고 2시간치 즉시 (하루 2회) — 출시 후 검토 |
| 해금 | 1구간 보스 격파 후 |

- **시간 조작 방지:** 인터넷이 될 때는 **서버 시간**으로 계산. 오프라인이면 기기 시간을 쓰되, 시간이 **뒤로 간 걸 감지하면** 그 구간은 0으로 계산하고 최대 12시간을 넘지 않게 한다.
- ⚠️ 하루 두 번 받으면 🪙 약 3,600~6,000 → **[Economy](Economy.md) 하루 골드 목표(약 6,000)를 넘을 수 있다.** 순찰을 목표에 포함해서 던전 보상을 맞추거나, 시간당 값을 낮춘다.

### 9-1. 종류와 동의

| 종류 | 예시 | 보내는 방식 | 동의 |
|---|---|---|---|
| **정보성** | "하트가 다 찼어요", "순찰 보상이 가득 찼어요", "길드 보스가 시작됐어요" | **로컬 알림** (기기에서 예약, 서버 필요 없음) | 앱 알림 권한 |
| **광고성** | "할로윈 이벤트 시작!", "시즌 패스 할인" | 원격 푸시 (FCM 등, 출시 후) | **별도 수신 동의** |

- **Android 13+**: 알림 권한(POST_NOTIFICATIONS)을 실행 중에 물어봐야 한다. **첫 실행에 바로 묻지 않고**, 첫 판이 끝난 뒤 "순찰 보상이 가득 차면 알려드릴까요?"처럼 이유를 붙여서 묻는다.
- **한국 정보통신망법 (광고성 정보, 출시 전 확인):**
  - 광고성 알림은 **사전 수신 동의**가 필요하다.
  - **밤 9시 ~ 다음 날 아침 8시**에 보내려면 **별도 동의**가 더 필요하다.
  - 알림 제목 앞에 **"(광고)"** 표시, 수신 거부 방법 안내.
  - 수신 동의 여부를 **정기적으로(2년마다) 다시 알려야** 한다.

### 9-2. 이 게임의 규칙 (법보다 엄격하게)
- **밤 9시 ~ 아침 8시에는 정보성 알림도 보내지 않는다.** (Economy 하트 원칙과 같음)
- 하루 최대 **2회**
- 설정에서 종류별로 끄고 켤 수 있다 (하트 / 순찰 / 길드 / 이벤트)
- "안 들어오면 손해" 문구 금지. ("보상이 사라져요!" ✖ → "순찰 보상이 모였어요" ⭕)

## 18. 🔧 점검 · 강제 업데이트 · 버전 확인

```
앱 시작 → Remote Config에서 읽기: min_version, latest_version, maintenance
   ├─ 점검 중 → 점검 화면 (예정 종료 시각, 공지 링크)
   ├─ 내 버전 < min_version → 강제 업데이트 화면 [스토어로]
   ├─ 내 버전 < latest_version → "새 버전이 있어요" [업데이트] [나중에]
   └─ 통과 → 로비
```

- 업데이트는 Google Play **인앱 업데이트 API** (강제 = 즉시형, 선택 = 유연형)
- **점검 중에는 접속을 막는다.** (오프라인 플레이를 허용하면 점검 후 데이터가 꼬일 수 있다)
- 점검 보상: 예정보다 길어지거나 1시간 넘으면 우편으로 💎 50~100
- 앱 버전과 **저장 데이터 구조 버전**을 따로 관리한다. ([GameDesign 12-2](../GameDesign.md#12-2-설계-원칙))
