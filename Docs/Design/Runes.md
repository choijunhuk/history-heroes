## 1. 한 줄 요약

**룬 = "이번 판에 불 빌드를 노릴래" 같은 방향을 정하는 장치.** 레벨업 카드에서 특정 태그 스킬이 **같은 등급 안에서** 조금 더 잘 나오게 한다.

| 절대 규칙 | 이유 |
|---|---|
| **등급 추첨은 절대 안 바꾼다** | 전설이 나올 확률은 룬이 있든 없든 같다 ("전설은 귀하다") |
| **후보에 없던 스킬을 넣지 않는다** | 다른 영웅 전용 스킬, 칸이 꽉 찬 종류의 새 스킬은 여전히 안 나온다 |
| **조합 카드에는 영향 없음** | 조합 카드는 조건을 채우면 확정이다 |
| **리롤 횟수 변화 없음** | 판당 2회 그대로 |
| **능력치를 주지 않는다** | 룬은 공격력·체력을 올리지 않는다. 힘 예산 표에 룬이 없는 이유 |
| **뽑기 없음, 판매 없음** | 보스 보상과 골드로만 얻는다 |

## 2. 동작 원리

[레벨업 카드 뽑기](../GameDesign.md#6-4-레벨업-카드-3장-뽑기-규칙)의 **2단계 ② "그 등급의 후보 중에서 스킬을 하나 뽑는다"**에만 끼어든다.

```
① 등급 뽑기 (일반/희귀/전설)  ← 룬 영향 없음
② 그 등급 후보 중 스킬 뽑기   ← 여기서 태그가 맞는 스킬의 가중치 × 룬 배율
```

### 예시: 희귀 등급이 뽑혔고, 후보가 4개일 때

| 후보 (희귀) | 태그 | 룬 없음 | 🔥 불의 룬 Lv2 (×2.0) |
|---|---|---|---|
| 멀티샷 | 투사체 | 1 → **25%** | 1 → 20% |
| 흡혈 | 생존 | 1 → **25%** | 1 → 20% |
| 낙뢰 | 번개 | 1 → **25%** | 1 → 20% |
| 불꽃 장판 (희귀일 경우) | 불 | 1 → **25%** | **2 → 40%** |

- 전설이 나올 확률(①)은 그대로다. 불 스킬이 "희귀 카드 중에서" 더 잘 나올 뿐이다.
- 화면에도 이 표처럼 **실제 확률 변화**를 보여준다. ("희귀 카드 중 불 스킬: 25% → 40%")

## 3. 룬 종류 (출시 7종)

| 룬 | 태그 | 노리는 빌드 | 얻는 곳 |
|---|---|---|---|
| 🔥 **불의 룬** | 불 | 지속 피해형 (불꽃 장판, 불 화살) | 2구간 보스 최초 격파 (3종 중 선택) |
| ⚡ **번개의 룬** | 번개 | 번개 광역형 (낙뢰, 테슬라 코일) | 2구간 보스 최초 격파 (3종 중 선택) |
| 🏹 **투사체의 룬** | 투사체 | 연사형 (멀티샷, 관통, 튕김) | 2구간 보스 최초 격파 (3종 중 선택) |
| ⚔️ **근접의 룬** | 근접 | 칼날 탱커형, 관우 | 골드 상점 |
| 🛡️ **생존의 룬** | 생존 | 흡혈, 방어력, 최대체력 | 골드 상점 |
| 📈 **수련의 룬** | 스탯 | 공격력, 공격속도 같은 기본기 | 골드 상점 |
| 🔗 **인연의 룬** | (특수) 조합 재료 | 조합 노리기 | 서바이벌 첫 클리어 |

### 🔗 인연의 룬 (특수)
- 태그 대신 **"지금 가진 스킬과 조합되는 재료"**의 가중치를 올린다.
- 예: 회전 칼날을 가지고 있으면 방어력(진화 재료)이 같은 등급 안에서 더 잘 나온다.
- 조합 자체를 쉽게 만들지는 않는다. 조합 카드는 여전히 조건을 채워야 나온다.
- **이미 발견한 레시피의 재료만** 해당된다. (레시피 발견의 재미를 지키기 위해)

## 5. 슬롯

| 슬롯 | 해금 |
|---|---|
| 룬 1칸 | 2구간 보스 최초 격파 (Economy.md와 같음) |

### 겹칠 때 규칙
| 상황 | 규칙 |
|---|---|
| 같은 룬 2개 | 불가 (같은 룬은 하나만) |
| 한 스킬이 두 룬에 모두 해당 (예: 불 + 투사체 태그를 가진 불 화살) | 배율을 곱하되 **최대 ×3.0** |
| 인연의 룬 + 태그 룬 | 위와 같이 곱하고 최대 ×3.0 |

## 6. 영웅별 장착과 모드

| 항목 | 규칙 |
|---|---|
| 인벤토리 | 계정 공용 |
| 장착 | **영웅마다 따로** 1~2칸 (관우는 근접의 룬, 테슬라는 번개의 룬처럼) |
| 같은 룬 동시 장착 | 영웅끼리 가능 (장비와 같은 "참조" 방식) |
| 던전 모드 | 적용 |
| 서바이벌 모드 | 적용 |
| 보스맵 | **효과 없음** (보스전에서는 레벨업을 하지 않으므로) |
| 기록 | 룬은 기록에 저장하지 않는다 (기록 용량과 무관) |

## 7. 획득처 정리

| 획득처 | 무엇을 |
|---|---|
| 2구간 보스 최초 격파 | 룬 슬롯 1 + 불·번개·투사체 중 **1개 선택** |
| 4구간 보스 최초 격파 | 룬 슬롯 2 + 선택 안 한 나머지 2개 중 1개 선택 |

| 🪙 골드 상점 (룬 슬롯 해금 후) | 근접·생존·수련의 룬 각 🪙 8,000, 보스 보상에서 못 고른 룬도 🪙 8,000 |

- 출시 7종 전부 **무료로** 얻을 수 있다.

## 8. 화면 흐름

```
[영웅 탭] → 영웅 선택 → [룬] 칸 (1~2칸, 잠긴 칸은 "4구간 보스를 깨면 열려요")
  └─ 칸 터치 → [룬 목록]
        └─ 룬 터치 → [상세]
              "희귀 카드 중 불 스킬: 25% → 40%"  (지금 영웅의 스킬 풀로 실제 계산)
              "전설이 나올 확률은 바뀌지 않아요"
              [장착] [강화 Lv2 🪙 3,000]
```

- 레벨업 카드 화면에서 룬 덕분에 뜬 스킬 카드에는 작은 룬 아이콘을 표시한다. (룬이 일하고 있다는 느낌)

## 9. 구현 구조

| 클래스 | 종류 | 역할 |
|---|---|---|
| `RuneData` | ScriptableObject | `id`, `targetTag` (또는 `isBondRune`), 아이콘, 설명 |
| `RuneTable` | ScriptableObject | 레벨별 배율, 레벨 비용, 상점 가격, 최대 배율 3.0 |
| `RuneInventory` | 저장 데이터 | 룬 ID별 레벨 (0 = 없음) |
| `HeroRuneLoadout` | 저장 데이터 | 영웅 ID별 룬 ID 최대 2개 |
| `RuneWeightModifier` | 런타임 | 판 시작 시 장착 룬으로 만들어짐. 스킬 뽑기 ②단계에서 후보별 배율을 돌려준다 |

### 뽑기 코드와의 연결 (중요)
- 스킬 뽑기(`PickSkills`)는 룬을 **직접 알지 않는다.** `IWeightModifier` 인터페이스로 배율만 받는다.
- 이렇게 하면 "등급 추첨에는 배율을 적용하지 않는다"가 **구조로 보장**된다. (등급 추첨 함수는 `IWeightModifier`를 받지 않음)

```csharp
public interface IWeightModifier
{
    // 같은 등급 안의 후보 하나에 곱할 배율 (1.0 = 영향 없음, 최대 3.0)
    float GetMultiplier(SkillData candidate, SkillLoadout currentLoadout);
}
```

### 직접 짜볼 부분 (연습)
- [ ] `RuneWeightModifier.GetMultiplier()`: 장착 룬 중 태그가 맞는 것의 배율을 곱하고 3.0으로 자르기 (8~10줄)

## 10. 결정 필요

- [ ] **룬에 작은 능력치도 줄까?** (예: 불의 룬 = 화상 피해 +10%)
  - 주면 룬 고르는 재미는 커지지만 판 안 스킬의 힘을 직접 올리게 된다
  - **추천: 주지 않는다.** 룬은 "방향"만, 힘은 장비·영웅이 담당. 역할이 겹치지 않는다.
- [ ] **🔗 인연의 룬을 넣을까?**
  - 조합 노리기를 돕지만, 조합이 너무 쉬워 보일 수 있다
  - **추천: 넣되, 발견한 레시피 재료에만, 배율은 다른 룬과 같은 ×1.5~2.5.** 조합 카드 확정 조건은 그대로라 안전하다.
- [ ] **룬 슬롯을 3칸까지 늘릴까?**
  - **추천: 출시 때 2칸.** 3칸이면 배율이 겹치는 경우가 많아져 빌드가 정해진 답처럼 된다.
