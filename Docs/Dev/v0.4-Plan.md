## 완료 기준 (GameDesign 11장 + Stats 4-3)
- 대표 보스에서 **"기본 성장 + 잘 짠 빌드"**가 **"높은 성장 + 대충 고른 빌드"**보다 쉽게 이기는가 (자동 벤치 + 사람)
- 같은 판 안 빌드로 **판 밖 0 계정 vs 판 밖 최대 계정** 보스 처치 시간 비율이 **3.0 이하**인가 (상시 능력치만이면 약 2.4)
- 판 밖 출처의 보조 능력치가 [Stats 4-1](../Design/Stats.md#4-1-보조-능력치-상한-판-밖-전체-합) 몫을 넘지 않는가 (테스트로 고정)

## 정해서 진행하는 것 (문서에 없던 빈칸, [제안] — 개발자가 바꾸면 따른다)
| 빈칸 | 이렇게 한다 | 이유 |
|---|---|---|
| 기록에 장비 말고 다른 판 밖 성장도 고정하나? | **영웅 레벨·별·수련·유물도 같이 고정** (7-3 "기록에 저장된 상태 그대로 싸운다"를 판 밖 전체로 넓힘). 수치는 최신 데이터 | "새 기록을 만들 이유"가 장비뿐 아니라 성장 전체에 생긴다. 일부만 고정하면 규칙이 헷갈린다 |
| 인벤토리 200칸이 넘으면? | 우편함이 아직 없어서 **새 장비는 자동 분해(🔩)하고 알림** | 우편함은 v1.0 (LiveOps). 그때 바꾼다 |
| 수련·룬·유물이 2구간 보스 뒤에 열리는데 2구간 보스가 없다 | 해금 조건은 문서대로 만들고, 시험은 **개발용 해금**으로. 2~5구간 보스는 로드맵에 따로 넣는다 | 해금 순서([Systems 3장](../Design/Systems.md#3-해금-순서))를 바꾸지 않는다 |
| 고급 상자 추첨을 서버에서? | v0.4는 **기기 안 추첨** (가짜 결제·가짜 보석). 서버 추첨은 [Monetization 8장](../Design/Monetization.md#8-결정-필요) 결정 때 | 출시 전 결정 항목 |
