# 🏹 역사영웅 로그라이크 — 게임 기획서

> 가제: **History Heroes (역사영웅 로그라이크)**, 정식 제목 미정
> 작성일: 2026-10-25
> 목적: 연습용 프로젝트 → 스토어 출시까지

---

## 1. 한 줄 소개

**전 세계 역사 인물이 되어 아처(Archero) 스타일로 던전을 돌파하고, 잘 나온 판의 빌드를 기록해 보스에게 도전하는 모바일 로그라이크.**

### 핵심 재미 3가지
1. **빌드 쌓기**: 방을 클리어할 때마다 랜덤 스킬 3개 중 1개를 골라 이번 판의 빌드를 만든다.
2. **귀한 전설**: 전설 스킬은 처음부터 끝까지 잘 안 나온다. 그래서 뜨면 짜릿하다.
3. **기록 → 보스**: 잘 나온 판을 기록으로 저장하고, 보스맵에 어떤 기록을 들고 갈지 고른다. (카제나의 세이브 데이터에서 착안)

## 3. 게임 흐름

```
[메인 화면]
   ├─ 영웅 선택 (+ 스킨 선택)
   ├─ 장비 / 룬 장착          ← v0.4 이후
   │
   ├─▶ [일반 던전]
   │     방 입장 → 적 처치 → 방 클리어 → 스킬 3개 중 1개 선택 → 다음 방
   │     ... 반복 ...
   │     판 종료 (사망 또는 클리어)
   │        └─▶ [기록 저장] 스킬 + 공격강화 레벨 저장
   │
   └─▶ [보스맵]
         저장된 기록 중 1개 선택 → 그 빌드 그대로 보스전
```

### 조작 (아처 방식)
- 가상 조이스틱으로 이동
- **멈추면 가장 가까운 적을 자동으로 공격**
- 움직이는 동안에는 공격하지 않음 (피하기와 공격 사이의 긴장감)

## 4. 영웅 (역사 인물 × 직업)

- 범위: **전 세계** 역사 인물
- 원칙: 역사적 업적이나 일화를 능력으로 바꾼다. (예: 과학자 → 마법사, 발명가 → 소환사)

| 직업 | 인물 후보 | 콘셉트 |
|---|---|---|
| 궁수 | 칭기즈 칸 | 기마궁수. 이동하면서 쏘기 |
| 궁수 | 이성계 | 신궁 전설. 백발백중 치명타 |
| 전사 | 관우 | 청룡언월도 회전 베기 |
| 전사 | 잔 다르크 | 깃발로 자신 강화 |
| 총잡이 | 나폴레옹 | 포병 출신. 대포 포격 |
| 총잡이 | 오다 노부나가 | 조총 3단 사격 |
| 법사 | 니콜라 테슬라 | 번개 연쇄 |
| 법사 | 제갈량 | 동남풍 바람술, 진법 |
| 소환사 | 이순신 | 거북선 소환 |
| 소환사 | 레오나르도 다빈치 | 발명품 소환 (비행기계, 전차) |

### 영웅마다 다른 것
- 기본 공격 방식 (화살 / 근접 / 총알 / 마법)
- 기본 능력치
- **전용 스킬** (예: 회전 베기는 관우만 나옴)

### ⚠️ 인물 선택 시 피할 것
- 독재자·전범 (스토어 심사와 여론 위험)
- 종교 창시자 (지역별 반발 위험)
- 근현대 인물 중 유족이나 재단이 이름·초상권을 관리하는 경우 (출시 전 확인)
- 특정 국가끼리 대결하는 구도 (해외 출시 시 반발 가능)

## 5. 스킨

**같은 인물을 스킨마다 다른 분위기로 표현한다. 능력치는 같고 겉모습만 바뀐다.**

```
관우
 ├─ 기본 스킨: 귀여운 SD (2등신)
 ├─ 코믹 스킨: 수염이 바닥까지 끌리는 패러디 관우
 └─ 진지 스킨: 웅장한 무신 관우 (판타지)
```

- 처음에는 **SD 기본 스킨만** 만든다.
- 스킨은 스토어 출시 후 추가한다. (수익원)
- 기술: Animator Override Controller를 써서 동작은 공유하고 그림만 바꾼다.

## 6. 스킬 시스템 (판 안 성장)

### 6-1. 스킬 데이터
스킬 하나하나를 ScriptableObject 에셋으로 만든다. 숫자만 바꿔서 밸런스를 조절할 수 있다.

| 항목 | 설명 |
|---|---|
| ID | 저장용 고유 문자열 (예: `multishot`) |
| 이름 / 아이콘 / 설명 | 카드에 표시 |
| 등급 | 일반 / 희귀 / 전설 |
| 태그 | `[불] [투사체] [근접]` 등. 영웅 전용 스킬, 룬, 시너지에 사용 |
| 최대 중첩 (maxStacks) | 스킬마다 다름 |
| 선행 스킬 | 이 스킬이 나오려면 먼저 가져야 하는 스킬 |
| 저장 비용 | 기록에 저장할 때 쓰는 포인트 |

### 6-2. 스킬 종류

| 분류 | 예시 |
|---|---|
| 스탯 | 공격력 +20%, 공격속도 +15%, 최대체력 +100 |
| 화살 변형 | 멀티샷, 사선 화살, 뒤쪽 화살, 관통, 벽 튕김 |
| 속성 | 불(지속 피해), 독, 얼음(둔화) |
| 소환·회전 | 주변을 도는 칼날, 따라다니는 펫 |
| 생존 | 흡혈, 레벨업 시 회복 |

### 6-3. 중첩 규칙 (스킬마다 다름)

| 스킬 | 최대 중첩 | 이유 |
|---|---|---|
| 공격력 +20% | 사실상 무제한 | 기본 성장 수단 |
| 멀티샷 | 3 | 너무 많으면 화면이 화살로 뒤덮임 |
| 불 화살 | 1 | 켜고 끄는 효과라 중첩 의미 없음 |

### 6-4. 3개 뽑기 규칙
1. 후보 고르기: 최대 중첩에 도달하지 않았고, 선행 스킬을 가진 스킬만 남긴다.
2. 층별 등급 가중치로 랜덤 3개를 뽑는다. (같은 스킬이 두 번 나오지 않게)
3. 후보가 3개보다 적으면 "체력 회복" 같은 기본 카드로 채운다.

### 6-5. 전설 확률: 처음부터 끝까지 귀하게
**초반에도 나올 수 있지만 확률이 낮고, 끝까지 가도 나오기 힘들게 한다. 확정 보장(천장)은 없다.**

| 구간 | 전설 확률 (예시) |
|---|---|
| 1~5층 | 약 1% |
| 6~15층 | 1% → 2.5% |
| 16층~끝 | 최대 약 4% |

- 확률은 에디터의 AnimationCurve(그래프)로 조절한다. 테스트하면서 맞춘다.

### 6-6. 스탯 계산 방식
```
최종 공격력 = 기본 공격력 × (1 + 모든 % 보너스의 합)
```
- 보너스는 리스트에 모아두고 매번 다시 계산한다. (스킬을 먹는 순서와 관계없이 결과가 같다.)
- 보너스마다 **출처**(스킬 / 장비 / 룬 / 영웅)를 붙인다. 장비와 룬을 나중에 쉽게 추가하기 위해서다.

### 6-7. 리롤
- 카드가 마음에 안 들면 **광고를 보고 3장을 다시 뽑는다.**
- 개발 중에는 가짜 광고(누르면 바로 성공)로 만들고, 출시 전에 진짜 광고 SDK로 바꾼다.

## 7. 기록 시스템 & 보스맵 ⭐ 이 게임의 핵심

### 7-1. 기록 저장
판이 끝나면 다음 내용을 **기록**으로 저장한다:
- 사용한 영웅
- 가진 스킬과 각각의 중첩 수
- 공격강화 레벨
- 도달한 층, 날짜

### 7-2. 기록 용량 (카제나 방식에서 착안)

| 스킬 등급 | 저장 비용 (예시) |
|---|---|
| 일반 | 1pt |
| 희귀 | 3pt |
| 전설 | 8pt |
| **기록 용량** | 30pt에서 시작, 성장할수록 늘어남 |

- 용량을 넘으면 **어떤 스킬을 남길지 직접 고르는** 화면이 나온다.
- 기록 용량 늘리기 = 판 밖 성장 요소
- 카제나처럼 저장이 확률로 실패하는 방식은 쓰지 않는다. (유저 불만 요소)

### 7-3. 보스맵
- 저장된 기록 중 하나를 골라서 그 빌드 그대로 보스전에 들어간다.
- 보스마다 상성이 있으면 "어떤 기록을 들고 갈까?" 고민하는 재미가 생긴다. (예: 불 면역 보스)

### 7-4. 미정 사항
- [ ] 보스전에 쓴 기록이 사라지는지(소모형), 계속 쓸 수 있는지(재사용형)
  - **추천: 재사용형.** 소모형은 긴장감은 있지만 초보 유저가 지치기 쉽다.
- [ ] 기록 슬롯 개수 (예: 처음 3개 → 늘릴 수 있음)

## 8. 판 밖 성장 (나중에 추가)

| 시스템 | 역할 | 예시 |
|---|---|---|
| **장비** | 기본 스탯 + 고유 효과 | 무기 공격력 +50, 갑옷 체력 +200 |
| **룬** | 어떤 스킬이 잘 나올지 조작 | 🔥 불의 룬: 불 태그 스킬 확률 ×2 |
| **영웅 성장** | 영웅 레벨, 능력치 | |
| **기록 용량** | 저장 가능한 포인트 증가 | 30pt → 40pt |

- 장비와 룬의 역할이 겹치지 않게: **장비 = 스탯, 룬 = 스킬 확률**
- 주의: 판 밖 성장이 너무 강하면 스킬 선택의 재미가 줄어든다.

## 11. 기술 메모

### 폴더 구조 (예정)
```
HistoryHeroes/            ← 저장소 루트
 ├─ Docs/                 기획서, 규칙, 아이디어 보관함
 └─ Game/                 ← 유니티 프로젝트 (Unity Hub에서 이 이름으로 생성)
     └─ Assets/
         ├─ Scripts/
         │   ├─ Player/      이동, 자동 공격
         │   ├─ Enemy/       적 AI, 생성
         │   ├─ Skills/      SkillData, SkillManager, 스킬별 효과
         │   ├─ Stats/       스탯 보정 계산
         │   ├─ Records/     기록 저장/불러오기
         │   ├─ Heroes/      HeroData, SkinData
         │   ├─ Ads/         IRewardedAdService, FakeAdService
         │   └─ UI/          스킬 카드, 기록 보관함
         ├─ Data/
         │   ├─ Skills/      스킬 에셋 (.asset)
         │   ├─ Heroes/      영웅 에셋
         │   └─ RarityTable.asset
         ├─ Prefabs/
         ├─ Scenes/
         └─ Art/
```

### 설계 원칙
- **스킬 효과는 스킬마다 `Apply()`로 따로 구현한다.** 거대한 switch문 대신, 새 스킬을 추가하면 파일 하나만 늘어난다.
- **저장은 ID로 한다.** 스킬 밸런스를 바꿔도 예전 기록이 깨지지 않게.
- **광고는 인터페이스 뒤에 숨긴다.** 개발 중엔 가짜, 출시 땐 진짜로 한 줄만 바꾼다.
- **태그 하나로 여러 문제를 해결한다.** 영웅 전용 스킬, 룬 확률, 시너지가 모두 태그 기반이다.
