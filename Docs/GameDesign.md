## 1. 한 줄 소개

**전 세계 역사 인물이 되어 아처(Archero) 스타일로 던전을 돌파하고, 잘 나온 판의 빌드를 기록해 보스에게 도전하는 모바일 로그라이크.**

### 핵심 재미 3가지
1. **빌드 쌓기**: 방을 클리어할 때마다 랜덤 스킬 3개 중 1개를 골라 이번 판의 빌드를 만든다.
2. **귀한 전설**: 전설 스킬은 처음부터 끝까지 잘 안 나온다. 그래서 뜨면 짜릿하다. **단, 전설 없이도 모든 보스를 깰 수 있다.**
3. **기록 → 보스**: 잘 나온 판을 기록으로 저장하고, 보스맵에 어떤 기록을 들고 갈지 고른다. (카제나의 세이브 데이터에서 착안)

### 🔁 핵심 순환 (게임이 멈추지 않는 이유)

```
 ┌──▶ 던전에서 빌드 만들기 ──▶ 기록 저장 ──▶ 기록 골라서 보스 도전
 │                                                    │
 │                                          보스 최초 격파
 │                                                    │
 └──── 새 보스는 다른 패턴 → 다른 기록이 필요 ◀── 다음 구간 개방
```

- **보스를 깨면 다음 구간(새 던전 + 새 보스)이 열린다.**
- 새 보스는 **패턴이 달라서** 예전 최강 기록이 항상 정답은 아니다. → 다시 던전에 들어가 새 기록을 만들 이유가 생긴다.
- 최초 격파 보상은 크게, 같은 보스 반복 격파 보상은 작게 한다. (같은 보스만 도는 게 최고의 성장 방법이 되지 않도록)

## 3. 게임 흐름

```
[메인 화면]
   ├─ 영웅 선택 (+ 스킨 선택)
   ├─ 장비 / 룬 장착          ← 나중에
   │
   ├─▶ [일반 던전] (구간별)
   │     방 입장 → 적 처치 → 방 클리어 → 스킬 3개 중 1개 선택 → 다음 방
   │     ... 반복 ...
   │     판 종료 (사망 또는 클리어)
   │        └─▶ [기록 저장] 남길 스킬 고르기 → 기록 보관함
   │
   └─▶ [보스맵]
         기록 1개 선택 → 그 빌드 그대로 보스전
         최초 격파 → 다음 구간 개방
```

### 3-1. 조작 (아처 방식)
- 가상 조이스틱으로 이동
- **멈추면 자동으로 공격한다.** 움직이는 동안에는 공격하지 않는다.

### 3-2. 전투 원칙 ("멈추면 쏜다"가 재밌으려면)
- **적은 공격 전에 예고하고, 공격 후 빈틈이 있다.** 플레이어가 "지금 멈춰서 두 발 쏠 수 있다"고 판단할 수 있어야 한다.
- 압박이 너무 강하면 공격할 틈이 없고, 너무 약하면 제자리에 서서 쏘기만 하는 게임이 된다. → 적 배치와 공격 주기로 조절한다.
- **표적 선택:** 사거리 안에 있고 벽에 가리지 않은 적 중 가장 가까운 적. 표적이 너무 자주 바뀌지 않게 한다.
- **멈춘 뒤 첫 공격까지 걸리는 시간**은 조정값으로 두고 실제 폰에서 맞춘다.

## 4. 영웅 (역사 인물 × 직업)

- 범위: **전 세계** 역사 인물
- 원칙
  - 역사적 업적이나 일화를 능력으로 바꾼다. (예: 과학자 → 마법사, 발명가 → 소환사)
  - **영웅마다 플레이에서 눈에 보이는 대표 효과가 1개 이상 있어야 한다.** 이름과 외형만 다른 직업이 되지 않게.
  - **핵심 조작 규칙("멈추면 쏜다")을 깨는 영웅은 만들지 않는다.** 차이는 공격 형태와 전용 효과로 만든다.
  - 영웅 설명에서 **사실 / 전승 / 게임 각색**을 구분해서 보여준다. (예: "📜 사실: 포병 장교 출신 · 🎮 각색: 대포 포격")

| 직업 | 인물 후보 | 대표 효과 |
|---|---|---|
| 궁수 | 칭기즈 칸 | 멈추는 순간 **공격 준비 시간 0** (기마궁수의 속사) |
| 궁수 | 이성계 | 신궁 전설. 일정 확률 백발백중 치명타 |
| 전사 | 관우 | 청룡언월도 회전 베기 |
| 전사 | 잔 다르크 | 깃발로 자신 강화 |
| 총잡이 | 나폴레옹 | 포병 출신. 대포 포격 (범위 피해) |
| 총잡이 | 오다 노부나가 | 조총 3단 사격 |
| 법사 | 니콜라 테슬라 | 번개 연쇄 |
| 법사 | 제갈량 | 동남풍 바람술, 진법 |
| 소환사 | 이순신 | 거북선 소환 |
| 소환사 | 레오나르도 다빈치 | 발명품 소환 (비행기계, 전차) |

### 영웅마다 다른 것
- 기본 공격 방식 (화살 / 근접 / 총알 / 마법)
- 기본 능력치
- **전용 스킬**: 영웅 ID로 명시적으로 지정한다. (태그로 정하지 않는다)

### ⚠️ 인물·주제 관리
- 피할 것: 독재자·전범, 종교 창시자, 유족이나 재단이 이름·초상권을 관리하는 근현대 인물, 특정 국가끼리 대결하는 구도
- 정복자나 전쟁 영웅은 지역마다 평가가 다르다. 출시 지역에 맞춰 검토한다.
- **보스는 실제 국가·민족이 아닌 가상의 존재로 만든다.**
- 그림·서체·음원은 출처와 이용 조건을 기록한다.

## 5. 스킨

**같은 인물을 스킨마다 다른 분위기로 표현한다. 능력치는 같고 겉모습만 바뀐다.**

```
관우
 ├─ 기본 스킨: 귀여운 SD (2등신)
 ├─ 코믹 스킨: 수염이 바닥까지 끌리는 패러디 관우
 └─ 진지 스킨: 웅장한 무신 관우 (판타지)
```

- 처음에는 **SD 기본 스킨만** 만든다.
- 스킨은 캐릭터 애착이 확인된 뒤(출시 이후) 추가한다. (수익원)
- 코믹 스킨도 인물을 비하하지 않는다. 유명한 일화를 재밌게 비트는 정도로.
- 기술: Animator Override Controller를 써서 동작은 공유하고 그림만 바꾼다.

## 6. 스킬 시스템 (판 안 성장)

### 6-1. 스킬 데이터
스킬 정의는 ScriptableObject 에셋으로 만든다. 숫자만 바꿔서 밸런스를 조절할 수 있다.

| 항목 | 설명 |
|---|---|
| ID | 저장용 고유 문자열 (예: `multishot`). 한 번 정하면 바꾸지 않는다 |
| 이름 / 아이콘 / 설명 | 카드에 표시 |
| 등급 | 일반 / 희귀 / 전설 |
| 태그 | `[불] [투사체] [근접]` 등. 효과 분류, 룬, 시너지에 사용 |
| 최대 중첩 (maxStacks) | 스킬마다 다름 |
| 선행 스킬 | 이 스킬이 나오려면 먼저 가져야 하는 스킬 |
| 저장 비용 | 기록에 저장할 때 **중첩 1개당** 드는 포인트 |
| 기록 가능 여부 | 1회성 효과(즉시 회복 등)는 기록에 남지 않음 |
| 용도 메모 | 던전 / 보스 / 둘 다. 보스전에서 쓸모없는 스킬이 너무 많지 않은지 점검용 |

### 6-2. 스킬 종류

| 분류 | 예시 |
|---|---|
| 스탯 | 공격력 +20%, 공격속도 +15%, 최대체력 +100 |
| 화살 변형 | 멀티샷, 사선 화살, 뒤쪽 화살, 관통, 벽 튕김 |
| 속성 | 불(지속 피해), 독, 얼음(둔화) |
| 소환·회전 | 주변을 도는 칼날, 따라다니는 펫 |
| 생존 | 흡혈, 즉시 회복(기록 불가) |

- 처치 시 발동 효과는 보스전에서 약해진다. 보스전에도 잡몹이 나오는 패턴을 넣거나, 보스용 대체 효과를 둔다.

### 6-3. 중첩 규칙 (스킬마다 다름)

| 스킬 | 최대 중첩 | 이유 |
|---|---|---|
| 공격력 +20% | 사실상 무제한 | 기본 성장 수단 |
| 멀티샷 | 3 | 너무 많으면 화면이 화살로 뒤덮임 |
| 불 화살 | 1 | 켜고 끄는 효과라 중첩 의미 없음 |

### 6-4. 3장 뽑기 규칙
1. **후보 고르기:** 최대 중첩에 도달하지 않았고, 선행 스킬을 가졌고, 이 영웅이 쓸 수 있는 스킬만 남긴다.
2. **카드 한 장마다:** ① 층별 확률로 **등급을 먼저 뽑고** → ② 그 등급의 후보 중에서 스킬을 하나 뽑는다.
3. 같은 스킬이 두 장 나오지 않게 한다.
4. 뽑힌 등급에 남은 후보가 없으면 한 단계 낮은 등급에서 뽑는다.
5. 전체 후보가 3개보다 적으면 "체력 회복" 같은 기본 카드로 채운다.

### 6-5. 전설 확률: 처음부터 끝까지 귀하게
**초반에도 나올 수 있지만 확률이 낮고, 끝까지 가도 나오기 힘들게 한다. 확정 보장(천장)이나 누적 보정은 없다.**

| 구간 | 카드 한 장이 전설일 확률 (예시) |
|---|---|
| 1~5층 | 약 1% |
| 6~15층 | 1% → 2.5% |
| 16층~끝 | 최대 약 4% |

- 확률은 에디터의 AnimationCurve(그래프)로 조절한다.
- 감 잡기: 카드 한 장 1%로 고정이면, 방 10개(카드 30장) 동안 전설을 한 번도 못 볼 확률은 **약 74%**다.
- 그래서 **전설 없는 판도 충분히 재밌어야 한다.** 일반·희귀 조합만으로 서로 다른 전투 방식이 나와야 한다.
- 전설은 "없으면 못 깨는 열쇠"가 아니라 **"플레이가 확 바뀌는 순간"**으로 설계한다.
- 확인할 지표: 전설 없이 끝난 판의 재도전률, 전설 미출현 연속 판 수

### 6-6. 스탯 계산 방식
```
최종 공격력 = (기본 공격력 + 고정 보너스 합) × (1 + % 보너스 합)
```
- 보너스는 리스트에 모아두고 매번 다시 계산한다. (스킬을 먹는 순서와 관계없이 결과가 같다.)
- 보너스마다 **출처**(스킬 / 장비 / 룬 / 영웅)를 붙인다.
- 공격속도, 둔화 같은 값에는 **상한·하한**을 둔다.
- 주의: 스탯은 순서와 무관하지만 관통·튕김·분열 같은 **투사체 효과는 순서가 중요**하다. 파생 투사체(튕긴 화살, 갈라진 화살)가 다시 효과를 발동하는지 스킬마다 정한다.

### 6-7. 리롤
- 카드가 마음에 안 들면 **광고를 보고 3장을 다시 뽑는다.**
- **판당 최대 2회** (임시값). 무제한이면 광고로 전설을 캐서 기록에 영구 저장하는 게 최선이 된다.
- 리롤은 "다시 뽑을 기회"이지 더 좋은 카드를 보장하지 않는다고 화면에 알린다.
- 광고가 실패하거나 취소되면 횟수를 차감하지 않는다.

## 7. 기록 시스템 & 보스맵 ⭐ 이 게임의 핵심

### 7-1. 기록에 저장되는 것
- 사용한 영웅
- 고른 스킬과 각각 저장한 중첩 수
- 공격강화 레벨
- **만들 당시의 성장 상태** (장비 등, 나중에 생기면)
- 도달한 층, 클리어 여부, 날짜, 기록 고유 ID

### 7-2. 기록 용량 (카제나 방식에서 착안)

**비용 = 스킬별 저장 비용 × 저장할 중첩 수**

| 항목 | 저장 비용 (예시) |
|---|---|
| 일반 스킬 | 중첩당 1pt |
| 희귀 스킬 | 중첩당 3pt |
| 전설 스킬 | 중첩당 8pt |
| 공격강화 레벨 | 레벨당 1pt (무료로 두면 비용 제한을 우회하는 통로가 됨) |
| **기본 용량** | 30pt (**임시값**) |
| **클리어 보너스** | 끝까지 클리어한 판은 용량 +10pt (임시값) |

- 용량을 넘으면 **어떤 스킬을 남길지 직접 고르는** 화면이 나온다.
- **유효성 검사:** 선행 스킬을 빼면 그 스킬이 필요한 후속 스킬도 같이 빠진다.
- **사망한 판도 저장할 수 있다.** 대신 클리어 보너스가 없어서, 필요한 스킬만 얻고 일부러 죽는 전략이 유리하지 않다.
- 용량 숫자는 **대표 빌드 몇 개의 실제 총비용을 측정한 뒤** 확정한다. 매번 다 들어가도 실패, 매번 핵심을 절반 버려야 해도 실패다.
- 카제나처럼 저장이 확률로 실패하는 방식은 쓰지 않는다.

### 7-3. 기록 사용 규칙 (확정)
- **재사용형:** 보스전에 써도 기록이 사라지지 않는다. 져도 잃지 않는다.
- 기록 슬롯은 처음 3개 (임시값)
- 보스전은 기록에 저장된 상태 그대로 싸운다. **현재 장비를 덧붙이지 않는다.** (그래야 새 기록을 만들 이유가 남는다)

### 7-4. 보스맵
- 구간마다 보스가 있고, 최초 격파 시 다음 구간이 열린다.
- **보스는 완전 면역 대신 패턴으로 빌드를 시험한다.**
  - 예: 짧은 빈틈에만 맞는 보스 → 순간 화력 빌드가 유리
  - 예: 잡몹을 계속 부르는 보스 → 광역·지속 피해 빌드가 유리
- 성공 기준: **플레이어가 보스에 따라 실제로 다른 기록을 고르는가.**

### 7-5. 패치(밸런스 변경) 정책
- 기록은 스킬 **ID와 중첩 수**만 저장한다. 수치는 불러올 때 최신 스킬 데이터에서 가져온다. → **밸런스 패치는 옛 기록에도 적용된다.**
- 스킬이 삭제되면: 그 스킬의 비용만큼 용량을 돌려주고 기록에서 뺀다. 플레이어에게 알린다.
- 패치로 비용이 올라 용량을 넘으면: 다음 사용 때 **남길 스킬을 다시 고르는 화면**을 띄운다.

## 8. 판 밖 성장 (나중에 추가)

| 시스템 | 역할 | 예시 |
|---|---|---|
| **장비** | **기본 스탯만** (고유 효과는 나중에 별도 설계) | 무기 공격력 +50, 갑옷 체력 +200 |
| **룬** | **같은 등급 안에서** 특정 태그 스킬이 잘 나오게 | 🔥 불의 룬: 희귀 등급 안에서 불 태그 가중치 ×2 |
| **영웅 성장** | 영웅 레벨, 능력치 | |
| **기록 용량** | 저장 가능한 포인트 증가 | 30pt → 40pt |

- 룬은 **등급 확률(전설이 나올 확률)은 건드리지 않는다.** "전설은 귀하다" 원칙을 지키기 위해서다.
- 균형 점검: 대표 보스에서 **"기본 성장 + 잘 짠 빌드"**가 **"높은 성장 + 대충 고른 빌드"**보다 쉽게 이겨야 한다. 반대면 판 밖 성장이 너무 강한 것이다.

## 11. 기술 메모

### 11-1. 폴더 구조 (예정)
```
HistoryHeroes/            ← 저장소 루트
 ├─ Docs/                 기획서, 규칙, 아이디어, 리뷰
 └─ Game/                 ← 유니티 프로젝트 (Unity Hub에서 이 이름으로 생성)
     └─ Assets/
         ├─ Scripts/
         │   ├─ Player/      이동, 자동 공격, 표적 선택
         │   ├─ Enemy/       적 AI, 생성, 공격 예고
         │   ├─ Skills/      SkillData(정의), SkillInstance(판별 상태), SkillManager
         │   ├─ Stats/       스탯 보정 계산
         │   ├─ Records/     기록 저장/불러오기, 유효성 검사
         │   ├─ Heroes/      HeroData, SkinData
         │   ├─ Ads/         IRewardedAdService, FakeAdService
         │   └─ UI/          스킬 카드, 기록 보관함
         ├─ Data/
         │   ├─ Skills/      스킬 에셋 (.asset)
         │   ├─ Heroes/      영웅 에셋
         │   └─ RarityTable.asset
         ├─ Prefabs/
         ├─ Scenes/
         └─ Art/
```

### 11-2. 설계 원칙

| 영역 | 규칙 |
|---|---|
| **정의 vs 상태** | ScriptableObject(`SkillData`)에는 **변하지 않는 정의만** 둔다. 중첩 수, 쿨다운, 발동 상태는 판마다 새로 만드는 런타임 객체(`SkillInstance`)에 둔다. SO 값을 플레이 중에 바꾸면 에디터에서 원본이 바뀌어버린다. |
| **`Apply()` 계약** | 기록을 불러올 때는 ① 플레이어 상태를 초기화하고 ② **총 중첩 수 기준으로** 다시 구성한다. 이벤트 구독은 해제 후 다시 등록한다. 두 번 불러와도 효과가 중복되면 안 된다. |
| **효과 구현** | 숫자만 다른 스킬은 공통 구현을 재사용한다. 새로운 동작이 필요한 스킬만 별도 클래스로. |
| **태그** | 태그는 효과 분류용. **영웅 전용 스킬은 영웅 ID로** 지정한다. 태그 조건은 AND/OR 의미를 명시한다. |
| **ID와 버전** | 에디터에서 ID 중복을 검사한다. 저장 파일에는 **저장 구조 버전**과 **밸런스 버전**을 따로 둔다. |
| **저장** | 임시 파일에 먼저 쓰고 → 성공하면 교체 + 백업 1개 유지. 방 클리어, 스킬 선택 확정 같은 **안전한 시점에 저장**한다. 모바일에서는 `OnApplicationQuit`가 호출된다고 믿으면 안 된다. 불러오기에 실패해도 기존 파일은 지운다거나 덮어쓰지 않는다. |
| **광고** | 인터페이스(`IRewardedAdService`) 뒤에 숨긴다. 가짜 광고에는 **성공 / 실패 / 취소 / 지연** 모드를 둔다. |

### 11-3. 저장 테스트 체크리스트
- [ ] 저장 → 불러오기 후 같은 빌드가 복원되는가
- [ ] 두 번 불러와도 효과가 중복되지 않는가
- [ ] 옛 버전 기록을 읽다 실패해도 원본 파일이 보존되는가
- [ ] 저장 중 앱을 강제 종료해도 이전 기록이 살아있는가

### 11-4. 직접 짜볼 부분 (연습)
- [ ] `PickSkills(candidates, count, floor)`: 카드마다 등급을 먼저 뽑고, 그 등급에서 스킬을 중복 없이 뽑기 (6-4 규칙)
