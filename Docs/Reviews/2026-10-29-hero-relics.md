# 새 영웅 유물·이야기 구현 검토

- 대상: `feature/hero-relics` 작업 트리, 2026-10-29.
- 범위: 유물 4개, 새 세트, 첫 클리어 지급, 이야기·기존 아이콘, 힘 예산, 파편 경제, EditMode 테스트.

## 결과

독립 코드 검토에서 기능상 수정 요청은 없었다. 기존 20개 정의·획득처·저장 ID가 그대로 유지되고, 새 영웅 4명의 `HeroFirstClear` 연결을 확인했다. 기존 `DungeonRun` 결과 처리와 `RelicService` 중복 방지를 그대로 쓴다.

- LOW: QA 최대 성장 설명에 남은 20개 표기 → 24개로 수정했다.
- 6세트는 각각 4개다. 별당 공격력·체력 1/12%, 세트당 공격력·체력·피해 감소 2/3%다. 전부 ★3이면 공격력·체력 +10%, 피해 감소 +4%다.
- 기존 유물도 보너스가 종전의 5/6이 된다. 저장된 별과 ID는 바꾸지 않는다. 기존 기록 역시 `MetaStats`의 최신 표 계산 규칙을 따른다.
- 별 올리기 총비용은 24 × (30 + 80) = 2,640개, 기록 용량까지 2,940개, 보험 교환 1회까지 3,060개다.
- 빌더 정의를 메모리에서 그대로 만드는 순수 EditMode 사례 19개를 작성했다. 별도 유물 모형 목록은 없앴다.

## 검증 근거

Unity를 실행하지 않고 설치된 Unity 6000.3.27f1 참조 DLL과 기본 템플릿 패키지 DLL을 사용해 Roslyn C# 9로 정적 컴파일했다. 에셋·장면 생성은 하지 않았다.

| 확인 | 결과 |
|---|---|
| Runtime 전체 소스 정적 컴파일 | 오류 0, 경고 604 (직렬화 필드 미할당 안내 등 기존 코드 경고 포함) |
| Editor 전체 소스 정적 컴파일 | 오류 0, 경고 0 |
| EditMode 전체 테스트 소스 정적 컴파일 | 오류 0, 경고 0 |
| 소스·문서 정합성 | 24개 고유 ID, 세트별 4개, 기존 20개 정의 보존, 재사용 아이콘 파일 5종, 비용·개월 계산 확인 |
| 변경 경계 | `.unity`·`.prefab`·`.asset`·폰트·금지 폴더 변경 없음. 새 C# 파일의 `.meta` 포함 |
| `git diff --check` | 통과 |

## 리드의 에디터 확인 범위

- **실행 미확인:** Unity 컴파일 파이프라인, EditMode 19개 실제 실행, 유물 상세의 아이콘·이야기·긴 글 줄바꿈. 정적 컴파일 결과를 테스트 통과로 보지 않는다.
- 빌더를 다시 실행해야 기존 테이블 수치·새 유물 에셋·상세 아이콘 참조가 갱신된다. 생성된 에셋과 `.meta`는 리드가 확인한다.
- 에디터에서 새 영웅 첫 클리어 결과와 재클리어, 교환 뒤 첫 클리어 환급을 확인한다.
- 이번 작업에서는 커밋하지 않았다.
