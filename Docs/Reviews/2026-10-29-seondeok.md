# 선덕여왕 구현 검토

작성: 2026-10-29 · 브랜치: `feature/seondeok`

## 결과

- 명단 10명, 해금, 전용 후보·진화·역할·미션·초상 연결을 검토했다. 독립 검토에서 추가 중대 코드 결함은 발견하지 못했다.
- 별자리 관측은 기본 공격 발사 경로에서 한 번만 소비한다. 이동·방 이동·영웅 교체·사망·비활성화 때 지우며, 액티브에서는 쓰지 않는다.
- 기존 코드에 있는 명단 전체 비교는 생략하지 않고 선덕여왕을 열 번째로 추가했다.
- 기록 구조와 기존 해금 서비스를 그대로 사용한다. 저장 버전이나 새 성장 체계를 추가하지 않았다.

## 검토로 고친 점

1. 별 사이 간격이 1.6이면 반경 1.4 밖에 있는 양쪽 별이 정지 목표를 맞히지 못했다. 간격을 1.2로 줄였다. 세 별이 모두 맞는 진화 Lv1은 합계 270%로 재료 Lv5의 240%보다 강하다. 실제 프리팹의 간격·반경·피해를 읽는 회귀 테스트를 추가했다.
2. 기존 `Fx.Orb`는 3D 재질과 꼬리를 푸른색으로 고정한다. 기본 구체에 `Fx.Starlight`를 연결해 기존 도형으로 보라·금색을 정했다. 테슬라의 구체는 기존 분기를 쓴다.

## 여기서 확인한 것

- 설치된 Unity **6000.3.27f1**의 참조 DLL과 현재 패키지 DLL로 Roslyn을 실행했다. 에디터 프로세스는 실행하지 않았다.
- `HistoryHeroes.Runtime`, `HistoryHeroes.Editor`, `HistoryHeroes.Tests.EditMode` 정적 컴파일: **세 어셈블리 모두 오류 0**. 런타임에는 직렬화 필드 미할당·폐기 API 등 경고 636건이 있다. 에디터·테스트 어셈블리 경고는 0이다.
- 선덕여왕 NUnit 테스트 **20개 사례 작성 및 컴파일**. 상태 테스트 11개는 최소 Unity 대체 타입과 실제 NUnit 환경에서만 통과했다. 이는 Unity EditMode 실행 통과를 뜻하지 않는다.
- 코드·문서 diff 공백 검사, 새 C# 네 파일의 `.meta`와 GUID 중복 검사 통과. 장면·프리팹·데이터·폰트 에셋은 변경하지 않았다.
- 컴파일 로그: `/private/tmp/history-heroes-seondeok-check/`. Git LFS 공용 임시 폴더 권한 때문에 전체 상태 조회는 실패하여 소스·문서·메타 경로를 따로 검사했다.

## 리드의 Unity 확인 순서

1. Play를 끈 뒤 `HistoryHeroes.EditorTools.Art3DAssets.Import()`를 실행한다.
2. `HistoryHeroes.EditorTools.Art3DCharacters.BuildAll()` 뒤 `HistoryHeroes.EditorTools.SceneBuilder.BuildAll()`을 실행한다.
3. 전체 EditMode 테스트를 실행한다. 새 연결 테스트는 위 빌더가 만든 데이터를 읽으므로 먼저 재생성이 필요하다.
4. 선덕여왕의 보라·금색 옷, 머리, 여자 손의 두루마리, 초상과 공격 동작을 확인한다. `Female_Peasant`는 `Female_Ranger`의 Avatar를 복사하며 프리팹 Animator에도 원본을 직접 연결한다. 가져오기 로그의 성공은 원본 Avatar의 유효성 검사다. 실제 대상 뼈대와의 결합·보행·공격 성공까지 입증하지 않는다.
5. 로비에서 선덕여왕을 선택해 별빛 점의 준비·이동 취소·한 번 소비, 멀티샷 묶음, 카드 창 일시정지, 방 이동 초기화를 확인한다. 보석 2,000 구매와 기존 단 한 번의 무료 선택도 확인한다.
6. Play에서 `QaTools.Scenario(3, "boss", false)`는 관측형, `QaTools.Scenario(4, "boss", false)`는 별자리형이다. 기존 프리셋 0~2와 이동 조건 `true`, 무리 `"swarm"`, 탄막 `"barrage"`도 비교한다. 수치는 화면·벤치 검증 전 시작값이다.

Unity 실행·기기 테스트·커밋은 이 작업에서 하지 않았다.
