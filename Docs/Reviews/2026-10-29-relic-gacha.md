# 유물 뽑기 구현·검토 인계

- 날짜: 2026-10-29 · 가지: `feature/relic-gacha` · 커밋은 하지 않음.
- 기준: 개발자 결정과 `Relics.md` 4~6장, `Gacha.md` 2-4장. Unity 실행·장면·프리팹·데이터 에셋·글꼴 수정은 하지 않았다.

## 설계

| 항목 | 결과 |
|---|---|
| 뽑기 대상 | 24종, 등급 없이 각 1/24. 영웅 연결 8종의 첫 던전 클리어 지급 유지 |
| 비용 | 파편 또는 보석으로 1회 100, 10회 900. 한 재화로 전액 지불, 자동 대체 없음 |
| 무료 | 광고 없이 하루 1회, 기존 `Clock.Today` 날짜 사용 |
| 보장 | 새 유물을 19회 연속 못 얻으면 20번째 미보유 중 균등. 새 유물 획득 시 0, 전종 보유 후 쉬며 ★3 보장은 없음 |
| 중복 | ★2에 1개, ★3에 추가 2개. ★3 초과는 파편 5 |
| 간소화 | 파편으로 직접 별 올리기·확정 교환 제거. 종전 고정 유물 보상은 조건마다 파편 20으로 한 번 지급 |
| 힘 예산 | 24종 ★3 공격력·체력 +10%, 세트 피해 감소 +4% 그대로 |
| 구매 전 공개 | 종류·개별 확률, 조건별 확률·보장, 중복 처리. 구매 근처에 사용 후 철회 제한 안내 |

## 경제 계산

`python3 Tools/relic_gacha_economy.py`, 고정 난수 729, 20,000계정. 7일째 해금·기록 용량 300 우선·무료 매일 수령·파편 900마다 10회·첫 클리어 8개 초기 지급을 가정했다. 일회성 파편 보상은 계산에서 뺐다.

| 조건 | 평균 뽑기 | 일수 | 30일 기준 개월 |
|---|---:|---:|---:|
| 30분 유저, 파편 17/일 | 198.90 | 173.69 | 5.79 |
| 60분 유저, 파편 33/일 | 199.25 | 151.15 | 5.04 |
| 30분 유저, 첫 클리어 지급을 전혀 계산하지 않음 | 207.88 | 181.22 | 6.04 |

보석을 쓰지 않아도 30분 유저의 종전 약 5.8개월을 유지한다. 보석 133/일은 장비 상자에 쓸 수 있다. 유물 10회에 보석 900을 선택하면 장비 고급 상자 3.6회(1회 가격 기준)를 포기한다. 60분 유저는 무료 횟수가 같아 종전 약 3개월보다 길어진다. 개인별 완성 시점은 보장하지 않는다.

## 저장 형식

- 구조 버전 **6 → 7**.
- `SaveData.relicGacha`: 새 유물 없이 연속 뽑은 횟수, 누적 뽑기 수, 무료 수령 날짜, 최근 결과 100개.
- `RelicStar.duplicates`: 다음 별까지 모인 중복. ★2에서 0~1, 다른 별에서는 0.
- 옛 저장은 새 횟수 0·날짜 없음·로그 없음이 올바르므로 별도 이관 분기를 추가하지 않았다. `Normalize`가 빠진 묶음을 채운다. 기존 유물·별·받은 조건 표시는 보존한다.
- 난수는 기존 `StreamRandom`을 별도로 만들어 쓴다. 판의 카드·적 난수 흐름을 바꾸지 않으며 테스트는 난수를 주입한다.
- `TryPull`은 작업 사본에서 전체 결과를 계산한 뒤 `Wallet`로 지불한다. UI는 `SaveSystem.Commit` 성공 뒤에만 결과를 보여 준다. 실패하면 지갑·별·중복·무료 날짜·보장·로그가 함께 되돌아간다.

## 리드가 에디터에서 확인할 것

1. 코드 반영 후 `SceneBuilder.BuildAll()`로 표·장면의 새 참조를 생성하고 6.3에서 컴파일한다. 기존 장면에는 새 UI 참조가 없다.
2. EditMode 전체를 실행한다. 특히 유물 뽑기·기존 유물·서바이벌 테스트를 확인한다.
3. 세로 1080×1920에서 상점 두 탭, 무료·파편·보석 결제, 확률 스크롤, 10장 결과, 초과 중복 표시를 본다.
4. 영웅 → 유물 → 뽑기 경로가 화면 맨 위에 열리는지, 돌아왔을 때 영웅의 힘과 유물 도감이 갱신되는지 본다.

실제 결제·서버 추첨·게임 밖 확률 공개 페이지는 기존 출시 계획 범위이며 이번 구현에서 실행하지 않았다.
