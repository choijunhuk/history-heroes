## 원문

검토 기준은 `main...feature/v0.2-core-loop`의 커밋 `bde46a8`입니다. 미커밋 변경은 제외했습니다. 아래는 정적 코드 검토 결과이며, Unity 실행·테스트는 수행하지 않았습니다. 파일은 수정하지 않았습니다.

1. **[P1] 저장에 실패해도 기록 저장 화면이 닫힙니다.**  
   위치: [RecordSaveScreen.cs:234](../../Game/Assets/Scripts/UI/RecordSaveScreen.cs:234), [SaveSystem.cs:56](../../Game/Assets/Scripts/Records/SaveSystem.cs:56)  
   디스크 부족 등으로 저장이 실패해도 `Save()`는 예외를 삼키고, `Commit()`은 즉시 로비로 이동합니다. 기록은 메모리에만 있어서 보관함에는 보이지만 앱 종료 후 사라집니다. 로비에는 dirty 데이터를 재시도하는 경로도 없습니다.  
   **수정:** 저장 성공 여부를 반환하고, 실패하면 선택 상태를 유지하면서 오류와 재시도 버튼을 보여주세요.

2. **[P2] 복구한 임시 파일을 다음 저장에서 바로 덮어씁니다.**  
   위치: [SaveStore.cs:80](../../Game/Assets/Scripts/Records/SaveStore.cs:80), [SaveStore.cs:46](../../Game/Assets/Scripts/Records/SaveStore.cs:46)  
   `Load()`는 정상적인 `.tmp`를 읽어도 본 파일로 확정하지 않습니다. 본 파일·백업 없이 완성된 `.tmp`만 남은 상태에서 복구한 뒤, 다음 저장 도중 앱이 종료되면 `FileMode.Create`가 유일한 정상 파일을 이미 잘라버렸으므로 기록을 잃습니다.  
   **수정:** 복구한 임시 파일을 보호된 본 파일로 확정한 뒤 다음 저장을 허용하거나, 별도 임시 경로에 새 데이터를 쓰세요.

3. **[P2] 백업 복구 후 저장하면 정상 백업이 손상 파일로 교체됩니다.**  
   위치: [SaveStore.cs:58](../../Game/Assets/Scripts/Records/SaveStore.cs:58)  
   본 파일 손상 → 정상 `.bak`에서 복구 → 저장 순서에서 정상 백업을 삭제하고 손상된 본 파일을 `.bak`로 옮깁니다. 이후 본 파일에 문제가 생기면 복구 가능한 이전 저장본이 없습니다.  
   **수정:** 검증에 실패한 본 파일은 정상 백업으로 회전시키지 말고, 복구에 사용한 정상 백업을 유지하세요.

4. **[P2] 레시피 변경 후 재선택하면 이미 만든 진화가 풀립니다.**  
   위치: [BossIntroPanel.cs:136](../../Game/Assets/Scripts/UI/BossIntroPanel.cs:136), [RecordDraft.cs:102](../../Game/Assets/Scripts/Records/RecordDraft.cs:102)  
   예를 들어 강철 회오리의 필요 패시브가 방어력에서 최대체력으로 바뀌고 비용도 올라가면, 옛 기록의 재선택 화면은 **현재 레시피**를 적용합니다. 최대체력이 없는 옛 기록은 회전 칼날 Lv5로 되돌아갑니다. GameDesign 7-5의 “레시피가 바뀌어도 기존 결과 유지”에 어긋납니다.  
   **수정:** 기존 조합 복원과 신규 조합의 재료 조건 검사를 분리하고, 재선택에서도 기존 결과 보존 정책을 유지하세요.

5. **[P2] 보스를 처치한 뒤 남은 탄환에 죽으면 패배로 확정됩니다.**  
   위치: [BossRun.cs:89](../../Game/Assets/Scripts/Modes/BossRun.cs:89)  
   보스 사망 후 승리 확정까지 1초 동안 전투가 계속됩니다. 그 사이 파동 탄환에 플레이어가 죽으면 `Finish(false)`가 먼저 실행되어 다음 구간이 열리지 않습니다. 결과 화면의 일시정지 때문에 승리 코루틴도 더 진행하지 못합니다.  
   **수정:** 보스 사망 이벤트에서 승패와 격파 저장을 즉시 확정하고, 결과 화면 표시만 지연하세요. 종료 후 피해도 차단해야 합니다.

6. **[P2] 방을 깬 뒤 문에 들어가기 전에 죽으면 기록 용량이 적게 계산됩니다.**  
   위치: [DungeonRun.cs:201](../../Game/Assets/Scripts/Dungeon/DungeonRun.cs:201)  
   깬 방 수를 항상 `_room - 1`로 계산합니다. 첫 방을 전멸시킨 뒤 남은 투사체에 죽으면 실제로는 한 방을 깼는데 용량이 0이 되어 기록을 남기지 못합니다.  
   **수정:** `OnRoomCleared()`에서 완료한 방 수를 별도로 기록하고 그 값을 사용하세요.

7. **[P2] 새 조합 발견이 다음 방 클리어까지 디스크에 저장되지 않습니다.**  
   위치: [RecipeBook.cs:18](../../Game/Assets/Scripts/Skills/Runtime/RecipeBook.cs:18)  
   조합 선택은 dirty 표시만 합니다. 다음 저장은 방 클리어 또는 판 종료이므로, 조합을 만든 뒤 앱이 백그라운드에서 종료되면 도감 발견을 잃습니다. 스킬 선택 확정도 안전한 저장 시점으로 지정한 12-2와 맞지 않습니다.  
   **수정:** 카드 선택 확정 뒤 `SaveIfDirty()`를 호출하고, 모바일 일시중단 시에도 미저장 변경을 처리하세요.

8. **[P2] 패치로 빠진 스킬을 플레이어에게 알리지 않습니다.**  
   위치: [BossRun.cs:62](../../Game/Assets/Scripts/Modes/BossRun.cs:62)  
   삭제·레벨 보정 이유인 `build.Notes`는 개발 로그에만 출력됩니다. 보관함도 보정된 목록만 표시하므로 플레이어는 기록에서 무엇이 빠졌는지 알 수 없습니다. GameDesign 7-5의 알림 요구가 누락됐습니다.  
   **수정:** 보스 시작 전 화면에 변경 내역을 표시하세요.
