# 보상 연출·영웅 정체성 감사와 수정

**2026-11-05 갱신:** 실행 도구의 제한이 해제돼 실제 Unity Play와 전체 EditMode **883/883** 검사를 통과했다. 아래는 최초 감사·당시의 차단 기록이며, 현재 결과와 전후 화면은 [실행 검증 보고서](2026-11-05-game-feel-validation.md)를 따른다.

날짜: 2026-11-04. 기준: `main`의 `317c61e`에서 분기한 `feature/reward-hero-identity`.

## 판단

게임의 차별점이 데이터와 코드에는 있지만 선택·발동·보상 순간에 잘 드러나지 않는 것이 가장 직접적인 문제였다. 뽑기는 목록이 바뀌는 수준이고, 영웅 상세에는 전용 액티브가 빠져 있었다. 세 법사의 전용기는 같은 별 그림과 원형 파동을 사용했다. 이 상태에서는 새 물건을 얻거나 다른 영웅을 고르는 기대가 약해질 수 있다. 실제 이용자의 이탈률을 측정한 결과는 아니며, 아래 코드·기존 화면에 근거한 제품 판단이다.

## 경제·저장·입력 경계

- 지급·재화 차감·추첨·천장 처리는 기존 `SaveSystem.Commit`과 서비스가 담당한다. `GachaReveal`은 저장과 추첨에 접근하지 않는다. 저장 실패·재화 부족 시 개봉하지 않는다.
- 장비·유물 1회/10회를 모두 처리하고, 최상 등급 또는 신규/승급 항목을 마지막에 공개한다. 10개 결과는 스크롤로 접근한다.
- 건너뛰기는 이미 저장된 결과를 전부 표시한다. 닫기·비활성화·다시 열기에서 잠금과 카드 표시를 복원한다. 광고 대기 중에도 구매를 막는다.
- 첫 카드 보장은 튜토리얼 고정 카드·이어하기의 offer 수·밴·소모 재료·가득 찬 슬롯·기존 보유 기술·조합 우선 규칙을 따른다. 첫 묶음에서 일반 → 희귀 순으로 교체할 자리를 찾고, 남은 비조합 카드가 모두 전설인 경우에도 전용기 보장을 우선한다. 따라서 **첫 묶음의 카드 구성은 변경**되며, 이후 카드/리롤과 상점 확률·가격·천장은 유지한다.
- 자동 액티브 발동과 멈춰서 기본 공격하는 조작, 저장 형식·ID·성장 수치·해금·과금은 유지한다.
- 개봉 모션은 unscaled 시간, 전투 쿨다운은 실제 게임 시간·실제 발동 상태를 따른다. 새 섬광/문양은 감소 효과 설정을 존중한다.

## 독립 검토에서 보완한 사항

1. 전용 진화만 검색하던 첫 구현을 모든 전용 합체까지 포함하도록 수정했다. 실제 21명과 SkillDatabase를 사용하는 검사도 추가했다.
2. 개봉 제목·확인 단추를 상하 앵커로 배치하고 결과 스크롤 높이를 가변으로 바꿨다. 페이지 높이 1600/1720/2140 경계 검사 코드를 추가했다.
3. 재개봉 시 이전 카드 삭제를 Play/EditMode에 맞게 처리했다.
4. 전용기 HUD의 보스 체력바 회피, 최초 미선택 안내, 채움 스프라이트, 재활성화 시 쿨다운 보존을 수정했다.
5. 도감의 발견한 전용 조합에도 같은 문양을 적용했다. 미발견 잠금 그림은 유지했다.

## 변경·인계 상태

- 기존 UI 키트·아이템 데이터·도감·스크롤·효과 풀을 재사용했다. 옛 뽑기 전역 포인터 기반 행 공개 코드를 제거하고 하나의 개봉 모달로 모았다. 새 의존성은 추가하지 않았다.
- 변경 코드는 `ShopPanel/GachaReveal`, `HeroPanel/CodexPanel/SkillCardView`, `SkillManager`, `HudView/HeroSkillHud/ActiveSkillBehaviour`, `HeroSkillArt/ConstellationBehaviour/AttackFx/RecordArchivePanel`과 새 검사 파일이다. 새 그림과 출처는 `Resources/UI/Gacha`·`Docs/Credits.md`에 있다.
- 현재는 해당 기능 브랜치의 **커밋 전 로컬 변경**이다. 프로젝트의 커밋 전 Editor 실행 규칙을 아직 충족하지 못해 커밋·push하지 않았다. 기존 beta.11 APK에는 이 변경이 포함되지 않았다.
- 작업 도중 외부에서 바뀐 `Game/Packages/manifest.json`·`packages-lock.json`의 Unity AI 패키지 설정은 별도 변경으로 보존했다. 이번 기능에 패키지를 요구하지 않는다.
- 작업 상태 쓰기 도구는 자동 승인 정책(`approval policy is never`) 때문에 거부됐다. 계획·검증·미실행 항목을 이 문서와 `Docs/Dev/GameFeelIdentity-Plan.md`에 남긴다.

## 2026-11-05 재개 점검

- 사용자의 계속 진행 요청으로 현재 브랜치·변경 내용을 재확인했다. 기존 재질 6개·폰트 2개는 여전히 작업 전 SHA256과 동일하다.
- Runtime 313개·Editor 56개·EditMode 검사 89개 소스를 다시 컴파일해 오류 0건을 확인했다. 기존 Runtime 경고 9개 외 새 경고는 없다. 변경 파일 공백 검사도 통과했다.
- Unity Pipeline은 실행 중 프로젝트를 찾았지만 서버는 계속 연결 불가이고 Safe Mode는 감지되지 않았다. 화면 접근도 `Computer Use was not approved to use Unity`로 거부됐다.
- 이번에도 실제 테스트·화면 검증을 실행하지 못했다. 현재 대화의 Unity 앱 접근 권한에 대한 질문을 보내 응답을 기다린다. 실행 검증 이전에 커밋하지 않는 상태를 유지한다.
- 새 확인 증거: [재점검 결과](Images/2026-11-05-runtime-recheck/recheck.json). 작업 상태 쓰기 도구도 같은 자동 승인 정책으로 계속 거부돼 문서에 재개 상태를 남겼다.
